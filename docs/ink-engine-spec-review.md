# 墨劍訣 · Ink Engine v1 規格審查

> 日期:2026-08-07
> 對象:《墨劍訣》Ink Engine v1 實作規格
> 結論:專業級規格,可直接據以開發;動工前務必先補下列四項技術盲點,並改為分里程碑實作。

## 總評
架構與美術紀律都正確,水準高於一般 AI prompt。它把「方向文件」產品化,補上了 API 介面、統一生命週期、物件池、Seeded Random、品質分級與可測的驗收標準。可以照這份做。

## 寫得好的地方(保留)
- **分層 Canvas**:inkCanvas 獨立、`pointer-events:none`、輸入交主層——專業做法。
- **統一生命週期 + 物件池**:active/age/duration/progress + reset,GC 壓力可控。
- **Seeded Random**:可重現墨痕,對除錯/重播極有價值。
- **品質分級 + auto(3 秒遲滯)**:避免頻繁抖動。
- **第十七節「永遠禁止」清單**:整份規格的靈魂,鎖死水墨語言,防止跑偏成霓虹/魔法。
- **驗收標準具體可測**:飛白真缺段、潑墨非規則圓、3 分鐘不漏記憶體等,內行。

## 必須先補的技術盲點(依重要性)

### 1. 最大盲點:缺「離屏烘焙」策略
規格是保留模式,每幀重算 Bezier + 多層毛邊 + reveal。40 條劍痕逐幀重繪,手機 45fps 吃緊。
**修正**:筆劃 reveal 完成後烘焙成離屏點陣,之後只 `drawImage` 貼圖,不再逐幀走向量。這是效能成敗關鍵。

### 2. multiply 混色跨層是誤解
inkCanvas 為獨立透明層,`multiply` 只會與 inkCanvas 上已畫的墨相乘,**不會與底下宣紙背景 canvas 相乘**,故「墨落紙上自然變深」跨不了層。
**修正**:二選一——(a) 墨與背景畫在同一張 canvas;或 (b) 放棄跨層 multiply,改用深色 alpha 的 source-over 疊加。PoC 採 (b)。

### 3. 溢位裁減策略未定義
有上限(40/80/10)但未定義超過時的行為。萬劍歸宗瞬間爆量時尤需規則。
**修正**:明訂「超過上限丟最舊」策略,並在 SkillComposer 端就限制 visual 數量。

### 4. SwordTrail 釋放未寫明
`createSwordTrail` 持有 getPosition 回呼綁著飛劍,劍消失若不回收即洩漏,會讓驗收第 14 條失敗。
**修正**:定義「劍死 → trail 釋放回池」的生命週期。

## 其他提醒
- **ES Modules vs 本機測試**:`file://` 直接雙擊會被 CORS 擋掉模組載入,需跑本機靜態伺服器或部署 Vercel。與「雙擊即玩」有取捨,dev 時用 `npx serve`。(本次 PoC 為求本機確認,採單檔非模組版,可直接雙擊。)
- **毛邊**:用輪廓不規則偏移(對),但要「有機」而非「鋸齒」有難度,可能仍需一點 alpha 紋理輔助。
- **inkCanvas 每幀清空**:應明講;依保留模式為是,這又回到盲點 1 的效能壓力。

## 範疇建議
與其一次要求「輸出全部完整程式碼、不得省略」(高風險),不如照規格第十五節「最小可運行 Demo」當里程碑一先做:BrushStroke + Splash + HitInk + InkInput + 物件池 + FPS,跑通畫線→飛劍→命中潑墨並達標,再逐步加 DryBrush / Diffusion / SwordTrail / SkillComposer。架構照這份走,分批交付、分批驗收。

## 一句話總評
架構與美術紀律都對,可照此開發;動工前務必補「離屏烘焙、multiply 跨層釐清、溢位裁減、trail 釋放」四點,並改為分里程碑實作。
