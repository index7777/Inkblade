## [2026-08-09] #86 散鋒改為「每把劍各走一份旋轉過的劍令」;長劍令加側向上限

**使用者**:「你的散鋒作法很奇怪,不是三把劍獨立飛行,畫面像這三把被綁定一塊。」

**根本問題**:`#85` 的錐面仍然是「相對移動中心做偏移」——
不管偏移算得多準,**所有劍都掛在同一個剛體上**,轉彎時整組一起轉,看起來就是一根有三個尖的叉子。

**新做法**:新增 `fanPose(c, a)`,把**劍令當下的位置繞「出鞘點」旋轉 a 弧度**。
每把劍因此走的是同一道筆跡的**旋轉副本** —— 你畫的彎它們各自都會彎,只是彎在不同地方、不同時間。
排位迴圈遇到 fan 直接走這條路徑,不再套 along/side。

**驗證方式**:畫一條有直角轉折的劍令,量「最外兩把劍的相對方位角」隨時間的變化。
```
散鋒:90 → 90 → 80 → 54 → 42 → 54 → 61   (持續變化 = 各自轉彎)
齊鋒:90 → 90 →  0 →  0 → 90 → 90 → 90   (跳變 = 剛體整組轉)
```

### 順帶修掉長劍令的副作用
繞固定原點旋轉,側向偏移會隨「離出鞘點的距離」線性長大:
```
修正前  畫長 400 → 外側劍離中心 306px
        畫長 900 → 463px
        畫長1800 → 925px(有一半時間在畫面外)
```
等於**畫得越長,外側那兩把越早飛出畫面,你付了長度卻只有中間那把在打**。
`fanPose` 加上「離劍令中心的距離上限」`min(300, 畫面寬×0.28)`:超過之後方向保留、距離不再拉開
(錐張到最大就轉成平行推進)。修正後三種長度都穩定在 300px,而獨立轉彎的特性不受影響。

**怎麼推回去**:`formationOffset` 的 fan 分支改回回傳 along/side,
排位迴圈移除 `off.fan` 分支,刪掉 `fanPose`/`FAN_PHI` 與劍令的 `ox/oy`。

## [2026-08-09] #85 散鋒改成真正的錐面(極座標 + 劍身跟著轉向)

**使用者**:「你的散鋒不是完整的扇型,要讓他真的是錐狀,不然劍多還是一樣跟齊鋒很像。」

**前兩版都只改了側向偏移**,所有劍的朝向仍然是 `c.ang` —— 劍一多就是一道越來越寬的**牆**,
不是錐。改用極座標:
```
半錐角 PHI = 0.52 rad(整錐約 60°)
張開距離 L = 間距×1.4 + min(已飛距離, min(320, 畫面寬×0.30))
along = L·cos(t·PHI) − L      side = L·sin(t·PHI)      劍身朝向 = c.ang + t·PHI
```
關鍵是**第三項**:劍身朝向跟著錐角轉,外側劍自然落後成弧,這才讀得出「散」。

**還修掉一個單位錯誤**:`spread` 原本傳的是 `c.age`(**影格數**),卻被當成像素用 ——
劍每幀飛 14px,錐面等於比劍慢十幾倍才張開。改成傳 `c.age × 飛行速度`(實際飛過的距離)。

**實測(6 劍,同一道直線劍令)**
```
散鋒 最大覆蓋寬 387px      齊鋒 最大覆蓋寬 99px
幾何(飛 400px):錐寬 388、前後深度 49、角度差 1.04 rad(≈60°)
齊鋒(任何距離):寬 100、深度 0、角度差 0
```
修正單位錯誤前散鋒只有 112px,跟齊鋒的 99px 幾乎一樣 —— 正是使用者說的「還是很像」。

**怎麼推回去**:`formationOffset` 的 fan 分支改回
`{along:-|t|*spacing*0.55, side:t*spacing*1.15}`;移除回傳的 `ang`、
排位處的 `sw.ang=c.ang+(off.ang||0)` 改回 `sw.ang=c.ang`;兩個呼叫點的 spread 改回 `c.age`。

## [2026-08-09] #84 移除滑過去的音效;效果文字把「幾成傷」改成看得懂的基準

### A. 滑鼠滑過按鈕不再有聲音
**這個 hover 音效不在主檔,在 `data/sound-system.js`** —— 我第一次找的時候只搜了
`inkblade.html`,回報「程式裡沒有滑過就響這件事」,那是錯的。
實際在 sound-system 尾端:
```js
document.addEventListener('pointerover', … play('uiMove'))
document.addEventListener('pointerout',  … )
```
整段移除。附帶的好處:觸控裝置的 `pointerover` 會在點擊前一瞬間補發,
原本等於**每次點擊都響兩聲**。點擊音效(`click` 監聽)保留。

**教訓**:查「有沒有這個行為」時只搜主檔是不夠的,玩法以外的行為有可能住在 data/ 裡。

### B. 「三成傷」看不懂 —— 全部改成標明基準
使用者:「三成傷很籠統看不懂。」確實 —— 三成是誰的三成?卡面沒有基準。
`FLAG_LABEL` 改為支援一個旗標拆成多行,並把所有比例值標上基準:
```
暴擊留飛白 三成傷   →  暴擊留下飛白 / 飛白 劍傷30%
飛白傷害 30%→70%    →  飛白 劍傷30%→70%
殘影補 25% 傷害     →  殘影補該擊 25%
潑墨留墨滴 35% 傷   →  潑墨處留下墨滴 / 墨滴 劍傷35%
墨滴化開再炸一次     →  墨滴化開再炸一次 / 波及 墨滴的60%
劍痕滯留 再傷 50%   →  收筆後劍痕滯留 / 碰到 劍傷50%
定身結束炸留白斬     →  定身結束炸留白 / 該斬 劍傷90%
滿劍意每三息召劍     →  滿劍意每三息召劍 / 召劍 劍傷70%
兩側各分一殘鋒       →  命中後兩側各分一殘鋒 / 殘鋒 劍傷20%
專注滿八層 傷害×2.2 →  專注滿八層 該擊×2.2
每折返一趟傷害 +30% →  每折返一趟 該擊+30%
每斬一隻 傷害+5%    →  每斬一隻 本劍+5%
```
基準用三種詞區分清楚:**劍傷**(基礎劍傷的百分比)、**該擊**(這一擊實際傷害的百分比)、
**本劍**(這把劍自己累加)。全部通過 9.2 版面寬度與 4 行上限檢查。

**怎麼推回去**:sound-system 加回 pointerover/pointerout 兩段;
`FLAG_LABEL` 的陣列值改回單一字串,`opLines` 移除陣列分支。

## [2026-08-09] #83 全卡稽核:25 項問題一次修完

用腳本逐張比對「效果有沒有寫出來 / 有沒有實際作用 / 有沒有跟本體重複」,查出 25 項。

### A. 22 個階級層「有效果但卡面空白」

全部補上白話說明(每條都通過 9.2 版面寬度檢查)。

### B. 飛白本來是純裝飾
使用者:「暴擊留下飛白,但飛白沒寫效果。」查證屬實 —— `whiteCut()` 只 push 一筆畫,
**沒有任何傷害**,要到斷意·大成才有。所以「暴擊留飛白」對玩家等於沒說。

改成**飛白本身就是一道斬痕**:每道生成後斬一次,基礎三成傷害;
斷意·大成 `whiteCutSlash` 改為「把它加深到七成」。
連帶讓鋒芒(養鋒·圓滿)、鎮痕·圓滿那兩處的飛白也真的有用。
```
飛白基礎 22 傷 → 斷意·大成 50 傷
```

### C. 斷意·小成與本體重複
小成給 `whiteCutOnCrit`,但**本體已經給了同一個旗標** —— 那一層是徹底的空氣。
改為 `whiteCutTwin`:暴擊改留兩道交叉飛白。

### D. 墨痕濃度是死欄位
使用者:「墨痕濃度也沒寫效果。」`mechanics.trailOpacity` **主檔零引用**,純裝飾標籤。
凝神的 `mul trailOpacity 1.05` 改成 `add stats.critChance 0.04`(與「心念專一」相符)。

### E. 劍速沒寫換算的傷害
使用者:「劍速加 3.6 但沒寫實際劍傷加多少。」劍速會轉傷害(`speedMul`),
但卡面只有「劍速 +3.6」,玩家算不出輸出。新增 `SPEED_MODEL`(與主檔同一組數字),
效果行改為 `劍速 +3.6 傷+15%`。

### F. 析鋒在沒有折返前是廢卡
使用者指出:分裂只在折返時發生,沒折返這張卡完全沒用,不該出現在池裡。
加上 `requires: ['momentum_return']`。實測:沒歸鋒時 `canOfferInsight` 為 false,取了歸鋒才 true。
(邊緣情況:只靠歸藏無痕拿折返的玩家仍看不到析鋒 —— `requires` 是 AND,無法表達 OR。)

### G. 齊鋒與散鋒的陣型幾乎一樣
使用者:「齊鋒跟扇型陣的效果重疊了,都是平行出劍。」查證屬實 ——
散鋒的 offset 只是「帶一點 V 形的平行」,而且**所有劍的朝向都是 `c.ang`**,看起來就是平行。

改成**隨飛行時間逐漸張開**(`open = 1 + min(2.2, age/70)`):
```
飛行影格      0    20    60   120
散鋒最外間距 115   148   214   312
齊鋒最外間距 100   100   100   100
```
齊鋒 = 固定間距的密集柱(集火),散鋒 = 越飛越寬的錐面(覆蓋面換密度)。兩者現在完全分得開。

**怎麼推回去**:見各節;`formationOffset` 多收的 `spread` 參數可直接忽略回到原公式。

## [2026-08-09] #81 卡片與階級表都改寫實際效果;**查出 22 個空的階級層**

### A. 旗標型效果現在也會顯示
原本 `effectLines()` 只認 add/mul/set/status —— **旗標型效果一行都印不出來**,
所以像散鋒式、歸鋒、貫鋒式這種「全靠 flag」的卡,效果模式一片空白,只能退回文案。

新增 `FLAG_LABEL`(白話說明,**數字直接抄主檔實作**,不是文案想像)與共用的 `opLines()`,
卡片與階級表吃同一份,兩邊永遠一致。沒列進 `FLAG_LABEL` 的旗標 = 主檔還沒接線,
**寧可不顯示也不要寫一個假的數字**。

### B. 靜觀「劍訣精進」列出三層的實際效果
原本只顯示進度條與「下一層 大成」,玩家不知道自己在追什麼。現在三層全列:
```
貫 貫鋒式  已臻 小成      420 / 500 斬 · 下一層 大成
   小成  每斬一隻 傷害+5%          已臻
   大成  末位破甲 受創+35%         500 斬
   圓滿  結束回刺首名 八成         1000 斬
```
已臻的用墨色,未臻的淡一階並標出門檻。新增 `runtime.tierLines(id, idx)`。

### C. 順帶查出的大洞:**21 個旗標沒接線,22 個階級層是空的**

寫 `FLAG_LABEL` 時逐一比對主檔,發現這些 flag 在 `inkblade.html` 裡**零引用**:

## [2026-08-09] #72 音效改走 WebAudio(每次出劍/受擊都會卡的真正共通點)

**使用者更正 #71**:「受擊不是四成以下才卡,是**每次**受擊都卡。」
#71 修的低血量劍環是真問題(15.6 倍)但不是這一個。

逐項量過受擊當下的每一種視覺效果(6 倍 CPU 節流,412×915 DPR2):

**全部在雜訊範圍內,畫面不是原因。**

### 剩下唯一同時發生在「出劍」與「受擊」的東西:音效

`play()` 的核心是
```js
audio.pause(); audio.currentTime = 0; audio.playbackRate = …; audio.play();
```
在 HTMLAudioElement 上做這組操作,會在**主執行緒同步重置一條壓縮音訊串流**。實測:
```
改前  首次 cast 5.2ms / hurt 4.7ms
      重複 cast 中位 1.8、最高 3.9ms
      重複 hurt 中位 3.5、最高 6.5ms
```
而 `SND.cast()` 只在出劍時呼叫、`SND.hurt()` 只在受擊時呼叫 —— 症狀與觸發點完全吻合。

### 修正:音效預先解碼成 AudioBuffer

`data/sound-system.js` 新增 WebAudio 音效層:
1. `unlock()`(使用者手勢)時建立 `AudioContext` 並 `fetch` + `decodeAudioData` 全部音效檔,存進 `buffers`。
2. `play()` 優先走 `playBuffer()`:建一個 `BufferSource` + `GainNode` 接上就 `start()`,
   **不碰任何 HTMLAudioElement**,沒有同步重置成本。
3. **保留原本的 HTMLAudio 音池當退路** —— `file://` 直接雙擊開啟時 `fetch` 會被瀏覽器擋掉,
   那時 `wa` 維持 false,行為與改版前完全一致。手機是連線上去玩(https),走得到 WebAudio。
4. `stopAll()` 一併停掉在播的 BufferSource。
5. 音樂仍走 HTMLAudio 串流(長檔案不該全解碼進記憶體)。

**改後(http 服務,同樣節流)**
```

重複 hurt 中位 0.9、最高 1.7ms(原本最高 6.5)
1500 幀壓力測試:平均 0.39ms、最慢 16.3ms、零例外
```

### 使用者可自行驗證的十秒測試

那是設計而不是效能問題,可以調成 2 或做成可關。

**怎麼推回去**:`data/sound-system.js` 移除 WebAudio 區塊(`actx`/`buffers`/`liveSources`/

## [2026-08-09] #71 手機卡幀:低血量時劍環每幀重新上色(15.6 倍代價)

**回報**:手機上「只有出劍跟受擊的時候會卡幀」。

### 真正的原因:`tintFrame()` 沒有快取

腳下的劍環在**血量低於四成**時會把每把劍染紅(`drawCircle` 那段的

```
血低於四成  37.4 ms / 幀     ← 15.6 倍,單這一項就掉到 27fps 以下
回滿        1.7 ms / 幀
```
使用者感受到的是「受擊之後開始卡」——受擊把血打到四成以下,劍環就開始每幀重新上色。

1. **`tintFrame()` 加快取**:`WeakMap<Image, Map<color, canvas>>`,同一張圖同一個顏色只烘一次。

2. **貼圖預先解碼**:`loadSword` 的 `onload` 補上 `im.decode()`。

   每次出劍都在那一幀現場解碼一張 651×260 的 PNG,這是「一出劍就頓一下」的部分。
3. **預烘紅色劍環**:`warmSwordTint()` 在載完後用 `requestIdleCallback` 先把 8 張 idle 幀的
   紅色版烘好。否則第一次掉到四成以下的那一幀要一次烘 8 張,剛好落在受擊瞬間。

**修正後(同樣條件)**
```
血滿 1.6ms / 血低於四成 1.6ms → 倍數 1.0(原本 15.6)
逐幀:中位 1.9ms,最慢 5.6ms(出劍那一幀)
```

**沒有動到的**:`inkTrail` 的多層筆劃成本會隨劍數線性上升(4 劍時約佔 draw 的 4 成),
那是持續成本不是卡頓尖峰,先不動。

**怎麼推回去**:`tintFrame` 改回共用 `_tintCv/_tintCtx` 的無快取版本並加回那兩行宣告;
`loadSword` 移除 `im.decode()` 與 `warmSwordTint()`。
