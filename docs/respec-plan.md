# 墨劍訣 · 洗點(洗墨重置)規劃

## 平衡規則(遊戲層,待接主檔 UI)
- 每局免費洗點 1 次;其後消耗本局劍意,遞增封頂:第2次30、第3次80、第4次150、第5次起250。
- 戰鬥中禁止洗點,僅休息點/悟道介面可用。
- 洗點清空場上蝕痕/鎮痕疊層;保留永久問道加成;真意/劍式/劍勢/劍意/修持全部重置;真意自動卸載需重抽。
- 每關通關給大量劍意(足夠 2–3 次付費洗點);BOSS 掉「洗墨丹」= 單局額外免費 1 次。
- UI:費用預覽、二次確認、道具優先抵扣、戰鬥中按鈕灰化。

## 已在 config runtime 提供的底層(data/game-config.js)
- `calcResetCost(resetTimes)` → 0/30/80/150/250(封頂)。
- `resetAllInsights(state)` → 回到 base+永久問道(採重建,無數值漂移),保留 `resetInsightTimes`。
- `undoInsight(state, id)` → 單條撤銷(見下方限制)。
- `BASE_RUN_STATE.resetInsightTimes` 追蹤本局洗點次數。

## 待主檔實作(遊戲/UI 層,非 config)
費用扣除、免費次數判定、戰鬥中禁止、洗墨丹抵扣、確認彈窗、面板刷新——這些屬 UI 邏輯,
接在主檔改用 runtime 時一起做(對應使用者提供的 handleResetAllBuild 範例)。

## 已知限制:undoInsight(單條撤銷)
單條撤銷採「逐階反向」。對含 `mul` 的悟道(如御劍追魂、破墨、部分真意),
在其後又疊了 `add` 時,乘除反向有順序誤差,可能小幅漂移;
劍式/真意的「當前生效」也非 ranks 能完整表達。
→ 建議:單條精準撤銷只用於純加算悟道;要完全歸零請用 `resetAllInsights`(重建,精準)。
若日後需要精準單條撤銷,應改為「記錄領悟順序(build history)+ 重建回放」架構。
