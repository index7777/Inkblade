## 二、三個必須先決策的設計風險

這三點會反過來影響資料結構,**建議在動工前先拍板**。

### 風險 1:靈力見底 = 無法防禦 = 必死

現在靈力只約束「畫多長」。加入彈幕後,靈力見底就等於**完全無法躲招**,這在站樁遊戲裡是死局,而且是最容易讓玩家覺得不公平的死法。

建議三選一(或組合):
- **A. 防禦不額外收費**:擋彈本來就是飛劍的副作用,不另計 —— 但長線仍受靈力限制;
- **B. 保底靈力**:靈力低於某閾值時回復速率大幅提升(「背水」),確保永遠畫得出一道短劍;
- **C. 短劍免費**:低於 N px 的劍痕不耗靈力,保證最低限度的防禦手段。

我的傾向:**B + C**。C 給下限保證,B 讓靈力見底變成「節奏懲罰」而不是「死刑」。

### 風險 2:60 波 × 14 秒 ≈ 14 分鐘一張圖

手遊單局偏長,而且 60 波都用同一套「衝向中央」的節奏會很膩。建議:
- 波次時長改為**資料驅動**(每張圖、每段可不同),前期短(8–10 秒)、後期長;
- 或改成**擊殺數推進**而非純計時,讓強 build 能加速推進(對應「高手靠靈活畫劍速刷」)。

### 風險 3:效能

現有紀錄:同時塗滿六層全螢幕曾經只有 6fps,靠烘焙圖層才回到 60fps。彈幕會帶來**彈數 × 飛劍數**的碰撞成本。
- 彈幕上限要硬性封頂(建議 ≤ 200),超出丟最舊;
- 碰撞用**均勻網格分格**(cell ≈ 64px),不要 O(n×m) 雙迴圈;
- 彈的繪製要貼圖化(像 `drawJian` 那樣烘一張),不要每顆走路徑繪製;
- 診斷面板(F 鍵)加上彈數 / 碰撞次數兩個計數,實機取數。

## 三、資料結構規劃(進 `data/game-config.js`)

新增三張表,與現有 INSIGHTS / REBIRTH 平行:

```js
ENEMIES   // 敵種:hp/半徑/速度/貼圖鍵/攻擊型態(近戰衝撞 or 射擊 pattern)/詞綴槽
ELITES    // 精英:繼承敵種 + 一個 counterMechanic(shield/split/devourReturn/cleanse)
BOSSES    // BOSS:phases[] { hpGate, skills[], parts[], seals[] }
LEVELS    // 關卡:{ id, scene, enemyPool, waves:[{range, tempo, spawnRate, affixes}], nodes:{10:elite,20:boss,...} }
DIFFICULTY// 難度 profile:{ casual:{hitboxScale:1.3, swordLinger:0.8, slowMult:2, bufferSec:25, freeRespec:Infinity}, challenge:{...} }
```

彈幕本身用 **pattern DSL**(和 op DSL 同精神),讓 BOSS 技能是資料而非程式碼:

```js
pattern('fan',   { count:12, spread:1.2, speed:3, kind:'normal' })
pattern('ring',  { count:24, speed:2.4, kind:'normal' })
pattern('aimed', { count:3, speed:5, kind:'heavy', hp:2 })
field('carpet',  { radius:180, dps:6, fadeByBlade:0.02 })   // 只能被「磨淡」
```

**封印**用獨立的 override 層,**絕對不要直接改 `runState`** —— 否則洗點快照、`resetAllInsights` 的「由永久快照重建」會全部失準:

```js
G.seals = { form:false, momentum:false, intent:false };
// syncStat() 尾端統一套用:if(G.seals.form) stat.count=1; ...
```

這樣封印是純表現層覆寫,解除只要清旗標,重塑劍意的精準歸零不受影響。

## 四、分期路線(每期都可獨立驗收、可玩)

### M1 · 彈幕地基(最關鍵,其他都疊在上面)
- `G.bullets` 實體 + 三型(普通 / 重型 hp2 / 墨域 field)+ 上限 + 網格碰撞;
- 飛劍 ↔ 彈碰撞 → 擊碎產生 `splash()`;
- **預覽線 telegraph**(先畫墨氣虛線,延遲後才發射);
- 判定放大係數、飛劍殘留時間接上 difficulty profile;
- 讓現有 tier2 墨獸偶爾吐一發,**不加任何新敵人就能驗收手感**。
> 驗收:能靠畫線擋掉彈、擋不掉會扣血、fps 不掉。

### M2 · 關卡導演 + 敵人資料層
- `ENEMIES` / `LEVELS` 進 config,`spawnEnemy()` 改讀敵人池;
- 波次改資料驅動(tempo / spawnRate / 詞綴),支援 60 波三段;
- 節點表:10/30/50 精英、20/40 BOSS、60 終極 BOSS、換圖;
- 波次 HUD 顯示「第 N 波 / 60」與段落名。
> 驗收:能跑完 60 波、三段節奏明顯、換圖切場景圖與敵人池。

### M3 · 精英(構築測試)
- 四個 counterMechanic 的鉤子:護盾(單發傷害門檻)、分裂、吞折返、清 debuff;
- 精英掉落:高稀有抽獎 + 大量劍意;
- 逆流派會坐牢 → 引導按暫停洗點(#23 已就緒)。
> 驗收:用錯 build 明顯打不動、洗點後立刻順暢。

### M4 · 留白安全區
- 封閉路徑偵測(首尾距離 < 閾值 → 視為封閉,閾值放寬並吸附);
- 多邊形內外判定 + 安全區生命週期 + 留白視覺;
- 一筆開天:長直線切開 field;萬劍歸宗:同心圓多層;斷意:面積 +30%。
> 驗收:全屏墨浪來時畫個圈能活。

### M5 · BOSS
- 部件子實體(可被飛劍打掉、影響階段技能);
- 三階段血線切換 + 技能表;
- 封印 debuff(走 override 層)+ 部件解除;
- **階段緩衝 15 秒**:暫停生怪、開悟道介面、免費洗點次數重置、掉洗墨丹;
- 擊殺後提升真意抽卡權重。
> 驗收:單一流派打不過、緩衝洗點後能過。

### M6 · 難度梯度與平衡
- 休閒 / 挑戰 profile 全面接線;
- 靈力保底機制(見風險 1)定案;
- 平衡打磨 + 音效 / 美術配套(預覽線、留白、擊彈潑墨)。

## 五、建議的起手順序

**M1 必須第一個做** —— 沒有彈幕實體,精英的「彈道壓力」、BOSS 的「全屏墨浪」、留白安全區全都無處可依。
M2 可以和 M1 併行(純資料層,不碰戰鬥迴圈)。
M4(留白)技術風險最高(手繪封閉圖形在手機上的辨識率),建議在 M1 完成後先做一個**只有偵測與視覺的原型**驗證手感,再決定是否納入 M5 的 BOSS 機制。

## 六、Demo 最小可交付範圍

若目標是「Demo 至少要完成 60 波三段 + 三隻 BOSS」,最小集合是:

**M1 + M2 + M3 + M5(簡化版 BOSS:單階段 → 三階段)**,M4 留白與 M6 梯度可延後。
其中 BOSS 先做**一隻**(千墨畫尊)跑通三階段 + 部件 + 封印 + 緩衝洗點,20 / 40 波的 BOSS 用同一套骨架換技能表即可 —— 這也正是把 BOSS 做成資料表的價值。
